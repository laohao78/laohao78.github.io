PTAM 证明了实时视觉 SLAM 是可行的。但它只是一个原型——代码是研究级的，场景是有限的，跟踪容易丢。

从 2007 到 2015，八年时间，视觉 SLAM 领域发生了三件事：**特征更好了，优化更快了，开源文化兴起了。**

这三件事的合流产生了一个炸弹。

---

## ORB-SLAM：把拼图拼成一张完整的图

2015 年，西班牙萨拉戈萨大学的劳尔·穆尔-阿塔尔（Raul Mur-Artal）在 GitHub 上释放了 ORB-SLAM。

在这之前的十年里，SLAM 的各个子模块都有人做出了突破性的改进：

- **ORB 特征**（Rublee 等，2011）：一种二进制图像特征，计算速度比 SIFT 快两个数量级，旋转不变，尺度不变，而且免专利费。Ethan Rublee 在 Willow Garage 做出来之后直接把它放进了公共领域。
- **g2o 图优化框架**（Kümmerle 等，2011）：把位姿图的稀疏性质用到极致，能实时求解包含数万个节点的非线性优化问题。
- **DBoW2 词袋模型**（Gálvez-López 和 Tardós，2012）：把图像转化成一组视觉单词的向量，快速判断两帧是否"看起来像"——这是回环检测的基础。
- **PnP 位姿解算的高效实现**——从 3D 地图点到 2D 像素点的投影关系，用 RANSAC 剔除误匹配，几毫秒内解出当前帧的精确位姿。

每个模块都有人做得很好了。但它们是分散的——独立的论文、独立的代码库、独立的数据格式。一个博士生想做 SLAM，需要先把这五个模块的代码拼在一起——每一块的接口都不一样，每一块的依赖都是互相冲突的版本。

穆尔-阿塔尔做了一件事：**他把所有的拼图拼成了完整的一张图。** 他把 ORB 特征提取、DBoW2 回环检测、g2o 后端优化、PnP 位姿追踪串成了一套系统——三个并行线程：

- **跟踪线程**（高频，每帧运行）：提取 ORB 特征，通过 PnP 估计当前帧位姿，决定是否创建新关键帧。
- **局部建图线程**（中频）：对最近的关键帧做局部 BA（Bundle Adjustment），优化附近的位姿和地图点，剔除冗余信息。
- **回环检测线程**（低频）：检测是否回到了曾经来过的地方。如果检测到回环，触发全局位姿图优化——"把所有位姿同时重新对齐，使误差均匀分布在整个轨迹上"。

ORB-SLAM 的一个核心设计决策是**基于关键帧**，而不是基于每一帧。不是每帧都参与建图和全局优化——只有那些被判定为"足够不同"的帧才会被提升为关键帧，进入后端优化流程。这使得系统的计算量变得可控——关键帧数量远少于总帧数，位姿图的规模保持在线性增长而非帧率增长。

2015 年，穆尔-阿塔尔上传了 ORB-SLAM 的代码。它依赖 ROS，依赖 OpenCV，依赖 Eigen，依赖 g2o，依赖 DBoW2，依赖 Pangolin。这套依赖树复杂得像一片森林。但每一个依赖都是开源的。它被编译、被配置、被运行起来的那个瞬间——全球的博士生们看到了一个地图和一条轨迹，以及那条轨迹上始终跟随着真值的虚线。

像一个从来没完整拼好过乐高的人，第一次看到整套乐高组装完后跑了起来。

## 直接法：另一种看世界的方式

ORB-SLAM 用的是**间接法**：先从图像中提取特征点（角点、边缘），然后在这些特征点之间做匹配，再从匹配中解算位姿。这种方法鲁棒、成熟——但有一个代价：你丢弃了图像中 99% 的像素信息。特征点之外的像素，SLAM 系统不看。

**直接法**走的是相反的路线：不提取特征。直接用两个图像的像素灰度值，通过最小化光度误差来估计位姿。

这依赖于一个叫"光度一致性假设"的前提——同一个 3D 点在不同帧中被拍摄时，在图像上的亮度应该是一样的。现实中这个前提经常不成立——光照变化、曝光变化、视角变化都会破坏光度一致性。但当一个场景的光照稳定、运动缓慢时，直接法能用上图像中几乎所有的信息——甚至是在墙壁、桌面上那些"没有角点"的平坦区域。特征法在这些区域是瞎的，直接法在这些区域有信号。

直接法的两个代表：

**DSO**（Direct Sparse Odometry），2016 年，慕尼黑工业大学 Jakob Engel。它只在有图像梯度的像素上做光度误差优化——既不是特征法的"只关心角点"，也不是稠密法的"关心所有像素"，而是一种"稀疏采样但直接使用像素值"的方法。DSO 在一个消费级笔记本电脑上可以实时运行，精度在 EuRoC 数据集上与 ORB-SLAM 接近。它的核心创新是把相机内参、曝光时间、镜头渐晕等一起放入优化框架——光度标定与几何估计同时进行。

**SVO**（Semi-direct Visual Odometry），2014 年，苏黎世大学 Christian Forster。SVO 先通过直接法快速估计初始位姿，再用特征法进行细对齐——把两种方法的优势结合起来。它的极致速度（400+ fps 在台式机上）是为无人机设计的——四旋翼的摄像头每秒需要做出几十次姿态修正才能不撞墙。

直接法和间接法的争论在 2015-2018 年间非常激烈。最后的结论不是谁赢了——而是**两者各有用武之地**。特征法在长期重访场景和大范围回环检测中占优，直接法在短距快速运动和弱纹理场景中占优。好的 SLAM 工程师会根据应用场景选择不同的前端方法，甚至动态切换。

## VIO：眼睛和内耳的拥抱

视觉 SLAM 有一个致命弱点：**快速运动中会丢。**

机器人在一个急转弯后，所有特征点都糊了——曝光时间不够短，运动模糊吞没了角点。跟踪线程报错。位姿丢失。

而 IMU——惯性测量单元——在快速运动中表现正好相反。陀螺仪和加速度计的采样率通常是 100-1000 Hz，几十倍于摄像头帧率。转弯越剧烈，加速度计给出的信号越强。IMU 不怕模糊。

反过来，IMU 的弱点是慢速漂移（第四章讲过了）。在静止或缓慢运动中，加速度计的零偏会累积——从停在原地开始，几分钟后它以为你已经走出了几十米。

视觉和惯性——这是天造地设的一对互补。

将两者紧密耦合的系统叫 **VIO**（Visual-Inertial Odometry）。耦合方式有两种：

- **松耦合**：视觉和 IMU 各自独立估计位姿，在卡尔曼滤波器里把两个估计融合在一起。实现简单，但丢掉了视觉几何约束和惯性动力学约束之间的交叉信息。
- **紧耦合**：视觉重投影误差和 IMU 预积分误差被放进同一个优化框架里——一个代价函数同时惩罚"图像特征匹配不准"和"IMU 加速度积分与实际运动不一致"。这是数学上更优的方案，也是主流方向。

**VINS-Mono**（秦通等，2017），香港科技大学。VINS 是紧耦合 VIO 路线上最广为人知的开源实现。它的核心技术创新包括：在线 IMU 标定（在运动过程中自动估计加速度计和陀螺仪的零偏与尺度因子）、鲁棒的初始化流程（从静止状态开始，通过一系列视觉-惯性测量自动恢复尺度、重力方向和初始速度）、以及一个滑窗优化器（维持最近若干关键帧和对应的 IMU 预积分约束，老帧被边缘化时其信息被压缩进先验因子）。

VINS-Mono 在 GitHub 上获得了 5100+ 颗星。秦通本人在访谈里说过，VINS 不是他一个人写的——沈劭劼教授在宾大写了最初的代码，杨振飞学长做了大规模重构，他接手后修复了初始化和标定模块，最后开源。"我是站在前人的肩膀上。"

在 VINS 之前，工业级 VIO 系统通常是闭源的——Google Tango、Apple ARKit、DJI 的飞控算法。VINS 的开源让每一个做无人机和手持 AR 设备的团队都拥有了一个可用的、可定制的 VIO 基线。这一下把 SLAM 从地面机器人推到了天上。

与 VINS 同时期的重要 VIO 工作还包括 **OKVIS**（Leutenegger 等，2015，基于关键帧优化的紧耦合 VIO）、**MSCKF**（Mourikis 和 Roumeliotis，2007，基于 EKF 的多状态约束滤波——比 VINS 更早但在 2010 年代被 Google Tango 和无人机广泛使用）、以及 **ROVIO**（Bloesch 等，2015，直接法+EKF 的紧耦合 VIO）。

## LIO：激光看见的世界

视觉 SLAM 和 VIO 有一个共同的阿喀琉斯之踵：**光。** 在黑暗的隧道里、在直射的阳光下、在大雾中、在没有任何纹理的白墙上——摄像头什么都看不见。IMU 可以撑几秒钟，但漂移会迅速累积。

激光雷达不怕暗。它主动发射激光脉冲，自己带光源。它不怕纹理缺失——一面白墙对摄像头来说是"没有特征"，对 LiDAR 来说是"一个平面，距离 3.2 米"。

LiDAR 的弱点是点云稀疏。Velodyne HDL-64E（2007 年发布，64 线，是 DARPA 无人车挑战赛的标配传感器）每秒钟产生约 130 万个点。听起来很多，但分布在 360° 的全景视野里，每一个角度方向的点密度远低于摄像头像素密度。这使得 LiDAR SLAM 的核心问题不是"找特征"，而是**如何在稀疏的点云中提取几何结构——平面、边缘、角点。**

**LOAM**（Zhang Ji 等，2014），卡内基梅隆大学。张楫在 2014 年 RSS 上发表的 LOAM（Lidar Odometry and Mapping）是 LiDAR SLAM 的奠基之作。它的核心思路是：提取点云中的**边缘点**（落在两个平面交界处的点——比如墙角）和**平面点**（落在一个平面上内部的点——比如地面）。在帧间匹配中，边缘点沿着边缘线的方向约束位姿，平面点沿着平面法线方向约束位姿。两种几何特征互补——一种约束切向，一种约束法向。

LOAM 的第二个关键设计是把里程计和建图分到两个线程。里程计线程高频运行（10 Hz），在连续帧之间做快速的几何特征匹配。建图线程低频运行（1 Hz），把最近的几帧累积成一个局部子图，在这个更稠密的子图上做更精细的位姿优化。这个"高低频配合"的架构直接影响了此后十年几乎所有的 LiDAR SLAM 系统。

**LeGO-LOAM**（Shan Tixiao 等，2018），史蒂文斯理工学院。单天笑是李泽湘教授的学生——大疆创始人汪滔的师弟。LeGO-LOAM 在 LOAM 的基础上做了三个关键改进：地面分割（先把地面点分离出来，单独对地面做约束——在室外地面上运行的机器人，地面的约束远强于其他特征）；点云聚类（去掉过于稀疏的孤立点簇——可能是树叶或噪声）；后端回环检测（基于 ICP 匹配的历史帧重访检测，一旦检测到回环就触发全局位姿图优化）。

LeGO-LOAM 在 KITTI 数据集上的表现超越了 LOAM，且计算量更低。它可以在 Jetson TX2（一个嵌入式 GPU 板）上实时运行——这对功耗敏感的移动机器人来说是关键。

### LIO：当激光遇见惯导

视觉+IMU 叫 VIO。LiDAR+IMU 叫 LIO。

单天笑在 LeGO-LOAM 之后继续沿着激光惯导耦合的方向推进。**LIO-SAM**（Shan Tixiao 等，2020），把 LiDAR 里程计因子、IMU 预积分因子、GPS 因子、回环检测因子统一表达在一个因子图上。和 LOAM 的两阶段估计不同，LIO-SAM 在一次求解中同时优化所有传感器的约束——这叫**平滑与建图**（Smoothing and Mapping），本质上是一个批量非线性优化问题。

LIO-SAM 的突破点在于**紧耦合**——IMU 预积分不是作为独立的位姿先验加进来，而是作为相邻两帧之间的运动约束直接参与因子图优化。LiDAR 帧间匹配提供相对位姿观测，IMU 提供高频运动约束，GPS 和回环提供全局锚点。所有约束在同一个代价函数里被同时最小化。

几乎与 LIO-SAM 同时，香港大学徐威的 **FAST-LIO**（Xu Wei 等，2021）走了另一条路线。FAST-LIO 使用**迭代扩展卡尔曼滤波（IEKF）**而不是因子图优化——在预测步骤中，IMU 做状态前向传播；在校正步骤中，LiDAR 点经过去畸变（motion undistortion）后与已有地图进行匹配，匹配残差被放入 IEKF 的更新方程中同时校正位姿和 IMU 零偏。

IEKF 的巧妙之处在于"迭代"——不是做一次线性化就完事，而是把同一个观测在当前估计附近反复线性化和校正，直到收敛。这使得它在大角度旋转和快速运动中比标准 EKF 更鲁棒。FAST-LIO 在一台板载电脑上可以达到 50+ Hz 的里程计输出——比实时还快。

FAST-LIO2（2022）进一步用**增量式 kd 树（ikd-Tree）**替代了全局地图的批量重建——每次插入或删除一个点时，ikd-Tree 在 O(log n) 时间内增量式地更新树结构，而不是重新构建整棵 kd 树。这一改让地图管理几乎不占 CPU 时间，里程计频率可以推到 100 Hz 以上。

**DLIO**（Direct LiDAR-Inertial Odometry，Chen 等，2023）则把"直接法"的思想从视觉搬到了激光。传统 LiDAR SLAM 在配准之前需要提取边缘和平面特征——这是 LiDAR 版的"特征法"。DLIO 跳过特征提取，直接在点云上做稠密点到平面的 ICP 匹配，用每个点落在其邻域平面的投影残差做优化——就像视觉直接法跳过特征检测直接用像素一样。

到 2023 年，LIO 和 VIO 都已经进化到各自的成熟形态。但它们谁也不能完全替代对方——LiDAR 在弱光弱纹理的室内、隧道、矿井场景中碾压视觉，视觉在远距离重识别和回环检测中碾压 LiDAR。所以第三条路出现了：**让它们成为同一个系统的两个子系统。**

## 多传感器：不只是视觉+IMU

随着机器人平台的复杂化，传感器种类越来越多。

- **激光雷达（LiDAR）**提供精确的深度信息，在弱纹理场景中不受影响，但重量大、价格贵、点云稀疏。
- **RGB-D 相机**（如 Kinect、RealSense）提供稠密深度图，消费级价格，但室外强光下失效。
- **轮式里程计**提供零漂移约束——"轮子不打滑时，我每转一圈就向前移动了一个车轮周长"——在室内平面运动中是极强的先验。
- **GPS/RTK**提供绝对参照——"你就是在这里，误差不超过 3 厘米"——但只在室外天空可见时工作。
- **UWB（超宽带）**在 GPS 不可用的室内提供绝对定位，精度约 10-30cm，需要预先部署基站。

**多传感器融合 SLAM** 的核心理念：**每一个传感器都有一个弱点，但没有一个弱点在所有传感器上同时出现。**

LVI-SAM（Shan 等，2021）把 LiDAR-SLAM 和 VIO 结合成一个双向耦合的系统——VIO 为 LiDAR-SLAM 提供初始位姿，LiDAR-SLAM 为 VIO 提供精确的深度和回环检测。任何一个子系统失效时，另一个子系统继续运行。这不是冗余，是互补。

多传感器融合的数学框架几乎无一例外地建立在因子图上。因子图是一个二分图——节点是待估计的状态（机器人的各个历史位姿、传感器的标定参数），边是约束（因子）。

- 视觉因子：第 i 帧中的特征点 j 在其在第 k 帧中的对应位置附近
- IMU 预积分因子：第 i 帧到第 j 帧之间的运动与 IMU 积分一致
- GPS 因子：第 i 帧的位置在 GPS 报告的坐标附近
- 回环因子：第 i 帧和第 j 帧看到了同一个地方

这些因子被塞进同一个非线性最小二乘问题，由 Ceres 或 g2o 求解。因子图的优美之处在于它的模块化——你可以在不修改框架本身的情况下添加或删除传感器因子。加一个新的传感器，就是加一种新的因子类型。

2015 到 2020，SLAM 从"一个博士生用一台笔记本跑一套算法"变成了"一辆自动驾驶汽车上的十几个传感器同时输出信号，每秒钟做数百次位姿估计，全局优化器每隔几分钟做一次城市的整体对齐"。

SLAM 不再是一个研究问题。它变成了基础设施。
